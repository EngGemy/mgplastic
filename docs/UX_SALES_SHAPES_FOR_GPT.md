# MG Plastic — أشكال المبيعات لتصميم UX (Brief لـ GPT)

> استخدم هذا الملف كمرجع وحيد عند تحسين واجهة المبيعات.  
> البيانات حقيقية من الـ API — لا تخترع حقولًا جديدة.  
> الاتجاه البصري المطلوب: **مظهر مالي–ديني** (ثقة، وقار، وضوح أرقام، بدون مبالغة ترفيهية).

تاريخ المرجع: 2026-10-21  
التطبيقات المعنية: موزع جملة · تاجر قطاعي · مخزن الدعوة · (مرجع للسباك عند الطلب)

---

## 0) برومبت سريع للصق في GPT

```
أنت مصمم UX/UI لتطبيق مبيعات B2B لمنتجات سباكة MG Plastic (ليبيا).
اتجاه الشكل: مالي–ديني — وقار مؤسسي، ثقة، وضوح أرقام، هوية عربية RTL.
ألوان مقترحة: أخضر زيتوني/فيروزي عميق + كريمي فاتح + ذهبي خافت للتأكيد (ليس neon، ليس purple AI).
ممنوع: كروت مكدسة بلا معنى، إحصائيات زائدة في الهيرو، نقاط لكل منتج، أسعار في كتالوج الشبكة.

ابنِ الشاشات التالية وفق هياكل البيانات في هذا الملف فقط:
1) شجرة التصنيفات (فئة رئيسية → فروع)
2) تبويب صناديق / قطع + شبكة منتجات
3) بطاقة منتج + تفصيل سريع للطلب
4) سلة/اقتباس نقاط مجمّعة
5) تفاصيل الطلب (timeline + بنود بالصناديق)

احترم القواعد الذهبية في القسم 1.
```

---

## 1) القواعد الذهبية (لا تكسرها في التصميم)

| يظهر في التطبيق | لا يظهر أبدًا في كتالوج/بنود الشبكة |
|-----------------|-------------------------------------|
| `total_points` على ملخص السلة / الطلب فقط | قيمة `points_per_unit` الرقمية |
| `has_points` (نعم/لا) كشارة خفيفة | `line_points` لكل بند |
| `order_unit` + `pieces_per_box` | أسعار `piece_price_*` / `box_price_*` (أدمن فقط) |
| الكمية بالقطع داخليًا دائمًا | اختراع «فرع متجر» كبُعد منتج |

**وحدات الطلب**

| `order_unit` | ماذا يعرض الزر/العداد | ماذا يُرسل للـ API |
|--------------|------------------------|---------------------|
| `box` | عدد **صناديق** | `{ "product_id", "boxes": N }` |
| `piece` | عدد **قطع** | `{ "product_id", "quantity": N }` |

تحويل داخلي: `quantity = boxes × pieces_per_box`.

**«فروع» في هذا النظام = فروع التصنيف** (`parent_id`)، وليست فروع محلات جغرافية.

---

## 2) التصنيفات والفروع (شجرة مستويين)

### النموذج الذهني

```
فئة رئيسية          parent_id = null
 └─ فرع (فئة فرعية) parent_id = id الرئيسية
      └─ منتجات     product.product_category_id → غالبًا على الفرع
```

### شكل عنصر التصنيف (موبايل — قائمة مسطّحة للفلتر)

```json
{
  "id": 5,
  "name": "محابس",
  "slug": "valves",
  "image": "categories/…",
  "image_url": "https://…/storage/…",
  "products_count": 12,
  "parent_id": 1
}
```

### شكل الشجرة الكاملة (API عام)

```json
{
  "id": 1,
  "parent_id": null,
  "name": "ملحقات",
  "slug": "accessories",
  "image": "https://…",
  "products_count": 40,
  "tags": ["محبس"],
  "children": [
    {
      "id": 5,
      "parent_id": 1,
      "name": "محابس",
      "children": []
    }
  ]
}
```

### UX مقترح (مالي–ديني)

- **الشريط العلوي:** اسم الفئة الرئيسية بخط عرض هادئ + عدد المنتجات كرقم صغير رمادي.
- **الفروع:** صف أفقى من «ألواح» مستطيلة (ليست pills دائرية) — صورة مربعة هادئة + اسم الفرع + عدّاد.
- **الفرع النشط:** إطار ذهبي خافت أو شريط سفلي أخضر عميق — بدون glow.
- **الكل:** خيار أول «كل الفروع» داخل نفس الصف.
- لا تضع Stats strip (إيرادات/نسب) فوق التصنيفات.

**تسميات عربية**

| مفهوم | النص |
|--------|------|
| Parent | الفئة الرئيسية |
| Child | الفئة الفرعية / الفرع |
| Filter chip | حسب التصنيف |

## 3) شكل المنتج (بطاقة القائمة)

### الحقول المتاحة للتطبيق (كتالوج الشبكة)

```json
{
  "id": 42,
  "name": "محبس ½",
  "description": "…",
  "image": "products/…",
  "image_url": "https://…",
  "points_per_unit": null,
  "has_points": true,
  "product_kind": "mg_points",
  "is_mg": true,
  "awards_points": true,
  "pieces_per_box": 12,
  "order_unit": "box",
  "category_id": 5,
  "category_name": "محابس",
  "available_quantity": 7
}
```

| حقل | عرض مقترح |
|-----|-----------|
| `image_url` | صورة منتج على خلفية كريمية/رملية فاتحة |
| `name` | عنوان أساسي — خط واضح عربي |
| `category_name` | سطر ثانوي رفيع |
| `order_unit` | شارة: **صندوق** أو **قطعة** |
| `pieces_per_box` | إن `box`: «12 قطعة / صندوق» |
| `has_points` | أيقونة نجمة خافتة فقط — **بدون رقم** |
| `available_quantity` | «المتوفر: 7» إن وُجد (مخزون الشبكة) — رقم هادئ |

`product_kind`: `mg_points` | `mg_no_points` | `shop` — استخدمه للفلترة الداخلية لا كـ badge مزعج.

### بطاقة المنتج — تكوين بصري

```
┌─────────────────────────────┐
│         [ صورة ]            │
│  محبس ½                     │
│  محابس · 12 قطعة/صندوق      │
│  ★ نقاط الولاء   المتوفر 7  │
│  [ − ]  2 صندوق  [ + ]      │
└─────────────────────────────┘
```

- العداد يزيد **صناديق** إذا `order_unit=box`، و**قطع** إذا `piece`.
- لا تكتب سعرًا. لا تكتب «نقطة/قطعة».

## 4) الصناديق وفروعها (منطق العرض)

الصندوق **ليس كيانًا مستقلًا** في الداتابيز — خاصية على المنتج ثم لقطة على الفاتورة.

| أين | الحقول | القاعدة |
|-----|--------|---------|
| منتج | `pieces_per_box` | `> 0` ⇒ يُباع بالصندوق |
| سلة API | `boxes` أو `quantity` | حسب `order_unit` |
| بند طلب (عرض) | `boxes`, `quantity`, `pieces_per_box`, `order_unit` | `quantity` = قطع دائمًا |
| بند فاتورة أدمن | `box_count`, `pieces_per_box`, `quantity` | POS |

### تبويبات الكتالوج (إلزامية في UX المبيعات)

استجابة القائمة تحمل:

```json
"units": { "all": 120, "box": 80, "piece": 40 },
"filters": { "order_unit": "box", "category_id": 5, "search": null }
```

ثلاث تبويبات أفقية بأسلوب دفتر مالي:

| تبويب | Query | عنوان عربي |
|--------|-------|------------|
| الكل | بدون / `all` | الكل |
| صناديق | `order_unit=box` | بالصندوق |
| قطع | `order_unit=piece` | بالقطعة |

تحت التبويب: صف فروع التصنيف (القسم 2).

### جملة العرض المعيارية للصندوق

```
3 صندوق × 12 قطعة = 36 قطعة
```

في السلة والتفاصيل استخدم نفس الصيغة حرفيًا.

## 5) تفصيل الطلب (Order Detail)

### رأس الطلب

```json
{
  "id": 55,
  "order_number": "ORD-…",
  "channel": "wholesale_to_retail",
  "channel_label": "من موزع الجملة للتاجر القطاعي",
  "status": "placed",
  "status_label": "بانتظار التأكيد",
  "status_description": "تم إرسال الطلب وبانتظار تأكيد المورّد.",
  "status_color": "warning",
  "is_open": true,
  "total_quantity": 46,
  "total_points": 120,
  "requester": { "id": 1, "name": "…", "brand_name": "…" },
  "supplier": { "id": 2, "name": "…", "brand_name": "…" },
  "note": "…",
  "timeline": [
    { "status": "placed", "label": "بانتظار التأكيد", "reached": true, "current": true }
  ],
  "available_actions": ["confirm", "ship", "reject"],
  "items": [ /* انظر بند البند */ ]
}
```

### بند داخل الطلب

```json
{
  "product_id": 42,
  "name": "محبس ½",
  "order_unit": "box",
  "pieces_per_box": 12,
  "boxes": 3,
  "quantity": 36,
  "points_per_unit": null,
  "line_points": null
}
```

### حالات وقنوات (نصوص جاهزة)

| `status` | `status_label` |
|----------|----------------|
| `placed` | بانتظار التأكيد |
| `confirmed` | تم التأكيد |
| `shipping` | في الطريق |
| `delivered` | تم التسليم |
| `cancelled` | ملغي |
| `rejected` | مرفوض |

| `channel` | `channel_label` |
|-----------|-----------------|
| `factory_to_wholesale` | من المصنع لموزع الجملة |
| `warehouse_to_wholesale` | من المخزن المركزي لموزع الجملة |
| `wholesale_to_retail` | من موزع الجملة للتاجر القطاعي |
| `retail_to_plumber` | من السباك للتاجر القطاعي |

### UX تفاصيل الطلب (مالي–ديني)

1. **ترويسة مستند:** رقم الطلب + قناة كسطر وثيقة (مثل سند مالي)، بدون بطاقة سميكة.
2. **Timeline عمودي رفيع** بألوان هادئة (`status_color`) — وصلات مستقيمة، أيقونات outline.
3. **ملخص أرقام في صف واحد:**  
   `إجمالي القطع: 46` · `مجموع النقاط: 120`  
   النقاط بلون أخضر عميق؛ القطع بلون نص أساسي.
4. **جدول بنود** (أسلوب كشف حساب):  
   اسم | وحدة | صناديق | قطع/صندوق | الكمية  
   بدون عمود نقاط للبند.
5. **إجراءات:** أزرار `available_actions` أسفل الصفحة — تأكيد / شحن / رفض — بنفس وقار الأزرار البنكية (ممتلئ للفعل الأساسي، outline للثانوي).

## 6) السلة / الاقتباس قبل الإرسال

`POST …/orders/quote` يعيد نفس شكل البنود + **`total_points` فقط** ذي معنى للنقاط.

### شريط سلة سفلي (Sticky)

```
┌──────────────────────────────────────────┐
│  5 أصناف · 36 قطعة                       │
│  مجموع نقاط الولاء: 120                  │
│  [ مراجعة الطلب ]                        │
└──────────────────────────────────────────┘
```

- لا تعرض نقاطًا لكل سطر في الشريط.
- زر المراجعة بلون أساسي عميق؛ الخلفية كريمية شبه بيضاء مع حد علوي رفيع.

## 7) اتجاه الشكل «مالي–ديني» (قيود تصميم)

### افعل

- RTL كامل، خط عربي جاد (مثال اتجاه: Cairo / IBM Plex Sans Arabic — ليس Inter).
- خلفية غير مسطّحة بالكامل: تدرج كريمي خفيف أو نقش هندسي إسلامي **باهت جدًا** (لا يزاحم المحتوى).
- أرقام الكميات والنقاط بوزن أوضح من العناوين الفرعية (وضوح «دفتر»).
- مسافات واسعة، قسم واحد = هدف واحد.
- ذهب خافت للتحديد النشط أو للشارات المهمة فقط.

### لا تفعل

- ثيم بنفسجي/نيون، glow، pills كثيرة، إيموجي.
- بطاقات داخل بطاقات في الهيرو.
- عرض سعر أو نقطة/قطعة في الكتالوج.
- لوحة إحصائيات مبيعات فوق قائمة المنتجات.
- تسمية «فرع» بمعنى موقع جغرافي داخل فلتر المنتجات.

### لوحة ألوان مقترحة (CSS variables)

```css
:root {
  --mg-ink: #1c1917;          /* نص أساسي */
  --mg-muted: #78716c;        /* ثانوي */
  --mg-paper: #f7f3ec;        /* خلفية ورقية */
  --mg-paper-2: #efe8dc;      /* سطح ثانٍ */
  --mg-trust: #0f5c4c;        /* أخضر ثقة / أساسي */
  --mg-trust-soft: #d8ebe4;   /* خلفيات شارات */
  --mg-gold: #b08d57;         /* تأكيد خافت */
  --mg-danger: #9f1239;       /* رفض / خطر */
  --mg-line: #e7e0d4;         /* فواصل */
}
```

## 8) خريطة شاشات المبيعات (للتنفيذ)

| # | شاشة | عناصر من البيانات |
|---|------|-------------------|
| A | كتالوج التوريد | `units` تبويبات + فروع `categories` + شبكة `items[]` |
| B | بحث | `filters.search` + نفس البطاقة |
| C | سلة | بنود مشتقة محليًا + `quote.total_points` |
| D | تأكيد طلب | ملخص أرقام + ملاحظة `note` |
| E | قائمة طلبات | `order_number`, `status_label`, `total_quantity`, `total_points` |
| F | تفاصيل طلب | timeline + جدول بنود بالصناديق + actions |

## 9) أمثلة نسخ عربية جاهزة للواجهة

| موضع | النص |
|------|------|
| تبويب | بالصندوق / بالقطعة / الكل |
| شارة وحدة | يُطلب بالصندوق · يُطلب بالقطعة |
| سطر صندوق | `{boxes} صندوق × {pieces_per_box} = {quantity} قطعة` |
| نقاط | مجموع نقاط الولاء |
| مخزون | المتوفر |
| فارغ صناديق | لا توجد منتجات تُباع بالصندوق في هذا الفرع |
| فارغ قطع | لا توجد منتجات بالقطعة هنا |
| طلب معلّق | بانتظار تأكيد المورّد |

## 11) ملخص بجملة واحدة لـ GPT

> صمّم واجهة مبيعات عربية وقورة (مالي–ديني): تصفح **فئة → فروع → تبويب صندوق/قطعة → منتج**، اطلب بالصناديق أو القطع، واعرض **مجموع النقاط مرة واحدة** على السلة/الطلب، مع تفاصيل طلب تشبه كشف حساب (timeline + جدول بنود) بدون أسعار أو نقاط لكل صنف.
